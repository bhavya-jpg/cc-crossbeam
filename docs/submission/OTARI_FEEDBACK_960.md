## 1. What worked well (834 chars)

Stable error codes: I could treat 402 insufficient_funds and over-budget as different cases and show a clear hold instead of a crash. Inline usage.cost_usd plus Otari-Conversation-Id made per-run cost easy: our first live run read a real 14-item Placentia corrections letter in 14 calls for $0.21. Streaming is solid: chat streams end with a usage chunk, and /responses ends with response.completed carrying the full response. Code execution was the best surprise: container auto returns otari-container-id, and passing it back let our analyst reuse one container across turns. Fallback was easy to show: when a primary model was refused, the backup answered on attempt 2, visible via Otari-Attempt-Count. GET /models caught that my first plan-reading model couldn't take images, and GET /tools says exactly why a tool is unavailable.

## 2. What didn't work (855 chars)

1) Non-streamed calls over ~30 s return CloudFront's HTML 504 with no Otari-Request-ID, so nothing to trace. Long vision and drafting calls hit it every time; streaming fixed it, but the docs don't warn you. 2) otari.ai has no hosted guardrails (not_configured); block mode without on_unavailable returns 502, a bad guardrail url only shows as evaluation_failed, and streams omit the Otari-Guardrails header. 3) The traces route answers a valid workspace key with "Invalid master key". 4) A nonexistent model returns 424 provider_not_configured, which reads like an account problem; the web-search 403 has no stable code. 5) With $0.00 every call is 402, so nothing could be tested; my first real call found otari_web_fetch rejects max_uses. 6) API reference pages returned 500 for much of my first session. Repro steps: OTARI_FRICTION_LOG.md in our repo.

## 3. What's missing / what would you change (723 chars)

A test mode: a key that returns realistic headers and tool behaviour without spending, so integrations can be checked before funds arrive. A documented limit, or a JSON error that keeps the request ID, for non-streamed calls over 30 s. Hosted guardrails on otari.ai, a verdict header on streamed responses, and guardrail scanning for image input: our corrections letter is a scan with no text layer, so text-only screening barely sees it. Per-request fallback across different models without a dashboard routing policy; I had to build it in the client, including narrowing tool sets when a tool is refused. Read access to a workspace's own traces with an API key, and a simple route that says what's left on a key's budget.
